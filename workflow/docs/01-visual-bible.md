# Visual Bible

## 2026-06-15 风格转向：Shared Dining 油画装置感

最新美术方向以用户参考图为准：BING-game 不再追求硬质暗色科幻 HUD，而应转向“共餐实验装置 / 当代艺术展 / 油画颜料流动”的视觉语言。核心观感是暖白展墙、透明亚克力容器、细金属支架、柔和投影、红/青/黄/蓝颜料颗粒与流体沉积，以及轻微画布笔触肌理。

执行原则：

- 背景优先使用暖白、米灰、浅画布色，不要大面积纯黑、深蓝或硬科技渐变。
- 面板像半透明玻璃、亚克力或展览标签，而不是 SaaS 卡片、后台面板或金属机甲 HUD。
- 桌面和战斗区域应像“颜料反应皿/共享餐桌装置”，允许红、青、黄、蓝颜料点和流体晕染表达状态变化。
- 线条使用细金属支架感：1px、低对比、结构清晰；避免粗重硬边框。
- 阴影要像展厅灯光下的柔和投影，不要电竞霓虹、不做发光堆叠。
- 角色和桌面资产后续也要转成手工绘制、油画/蛋彩质感；当前几何/半写实 blockout 只能作为技术占位。
- 角色最新方向为“手绘搞怪动物，但不过度可爱”：允许夸张动物轮廓、斜眼/困惑/较真等喜剧表情和生活化道具，不允许糖水萌宠、三国古风、真人偶像脸或塑料 3D 玩具感。
- 可读性仍然优先：主要按钮、倒计时、HP、饼数、已提交状态必须在浅色画布上清楚可见。

禁止项：

- 禁止继续把整体 UI 做成暗色深渊科幻、硬边控制台或普通网页后台。
- 禁止大面积黑底青绿 HUD。
- 禁止塑料玩具、简单几何体、纯程序材质。
- 禁止只靠渐变和光效制造“高级感”；必须有画布、颜料、透明装置或手工肌理线索。

这份文档用于固定《BING / 饼》的视觉和 UI 方向。每次一个界面被验证有效，就把规则沉淀到这里，作为之后 Codex、Figma、子智能体和美术资产制作的共同标准。

## 特效素材管线：imagegen 关键帧 + Seedance 补全

技能溅射、命中、反弹、防御、治疗和大招不应只靠 CSS 圆形、几何光效或简单粒子完成。推荐流程：

1. 使用 imagegen 生成 3-5 张油画关键帧：起势、爆发、扩散、回落、残留。
2. 关键帧保持同一构图和透明/浅色背景版本，画面语言使用颜料飞溅、油彩拖痕、透明液体波纹、细金属线振动。
3. 使用 Seedance 或同类视频补帧工具将关键帧补成 0.8-1.6 秒短动画。
4. 导出 WebM/MP4 与 PNG poster frame，前端按技能类型播放，失败时回退到 poster frame。
5. 每个特效必须保留游戏读数可见性：HP、饼数、目标线和提交状态不能被持续遮挡。

建议命名：

- `apps/client/public/assets/effects/{skillId}/keyframe-01.png`
- `apps/client/public/assets/effects/{skillId}/keyframe-02.png`
- `apps/client/public/assets/effects/{skillId}/poster.png`
- `apps/client/public/assets/effects/{skillId}/effect.webm`

首批优先级：

- `sha-splash`：红色油彩溅射，表示攻击命中。
- `defense-ripple`：青绿色透明波纹，表示防御。
- `rebound-snap`：蓝黑细线回弹，表示反弹。
- `heal-bloom`：暖黄/白色颜料晕开，表示治疗。

## Do

- 使用暖白画布、米灰墙面和低对比亚克力面板，让操作按钮和当前目标始终清楚。
- 重要按钮必须有明确 hover、pressed、selected、disabled 状态。
- HUD 只显示当前决策需要的信息：阶段、倒计时、已提交、未提交、目标、消耗。
- 桌面动画可以有冲击感，但不能遮掉 HP、饼、已出招状态。
- 移动端优先保证可玩：行动面板、提交按钮和当前选择不能被装饰压住。

## Do Not

- 不要塑料玩具感。
- 不要几何体拼装人、胶囊人、球形头贴五官，或任何一眼能看出是基础 primitive 组合的角色。
- 不要大圆角 SaaS 卡片感。
- 不要像普通网页后台或 CRM。
- 不要用无意义渐变、光球、背景装饰填空。
- 不要让文字解释 UI 动效；状态本身要能被看懂。

## UI Components

### Button

- Default: 浅色亚克力或薄画布底、细描边、图标在前、文字短。
- Hover: 边框和轻微投影同时提亮，不改变尺寸。
- Pressed: 轻微内压，持续时间 80-120ms。
- Selected: 使用青绿细线、淡颜料晕染或展签角标，必须比 hover 更明确。
- Disabled: 降低对比，不隐藏文字；能说明原因时放在 `title` 或附近提示。
- Controller focus: 2px 高对比描边，不能只依赖颜色变化。

### Panel

- Background: 暖白画布、半透明亚克力或展签纸面，避免纯黑和深色 HUD。
- Border: 1px 低对比细线，重点面板用颜料细边、透明压痕或小面积色点提示。
- Shadow: 柔和展厅投影，表现桌面层级，不做重黑阴影。
- Texture: 可用微弱纸纹、画布颗粒、颜料沉积和细金属支架线，但不能影响文字。
- Radius: 6-8px；大型工具面板可 10px，但不要胶囊化。

### HUD

- Position: 顶部显示阶段和进度；牌桌内保留展签式状态、颜料线索和目标连线；行动面板贴近底部或侧边。
- Information priority: 当前阶段 > 是否需要我行动 > 目标/消耗 > 倒计时 > 日志。
- Animation: 数值变化使用短促闪烁或滚动，持续 160-320ms。
- Collapse behavior: 移动端把日志、技能、规则收进 tabs；行动面板不可被折叠到找不到。

### Modal

- Entry animation: 120-180ms，轻微上移或缩放。
- Exit animation: 100-140ms，直接、干净。
- Confirm action: 主按钮使用 Accent 或 Warning，文案必须是动词。
- Cancel action: 次按钮弱化但可见，不使用危险色。

## Motion

- Hover: 80-120ms，按钮/座位轻微提亮。
- Click: 80ms 内给出按下反馈。
- Error: 220-320ms 轻微横向抖动或红色闪烁。
- Success: 180-300ms 绿色/青色脉冲。
- Damage or failure: 240-420ms 冲击波、短震、红色数字，但不能长期遮挡桌面。
- Reduced motion: 关闭大幅镜头晃动、粒子爆发和长位移，只保留透明度/颜色反馈。

## Character Art Direction

目标：把默认角色和玩家形象从 placeholder 推进到“手绘搞怪动物角色”，同时保持共餐装置牌桌的读局可读性。当前简单几何体、半写实真人 blockout 和程序化头像只允许作为技术调试占位，不能作为公开试玩美术资产。

### Proportion

- 默认使用动物拟人比例：大头但不幼态，短躯干，手脚和道具可夸张，整体更像法式手绘动画角色而不是 3D 娃娃。
- 轮廓必须一眼能分辨物种和玩法身份：耳朵、鼻口、尾巴、爪形、毛发或羽毛要成为剪影的一部分。
- 头部、肩部、手部和标志性道具可以夸张，以保证桌面距离和移动端头像可读。
- 避免过度 Q 版、糖水萌宠、偶像脸、三国古风、塑料玩具感和纯写实照片感。

### Materials

- Fur / feather / skin: 手绘色块叠加细线，保留动物特征和少量粗糙笔触，不做毛绒玩具渲染。
- Cloth: 低饱和布料、围裙、领巾、外套或护具，允许颜料污迹和生活化磨损。
- Leather / metal / acrylic: 只作为小面积道具、扣件和展架，不要把角色做成机甲。
- Paint marks: 角色可以带一点颜料痕迹，与技能 VFX 和共餐装置统一。
- No emissive body: 不做全身发光；技能光效只发生在道具、桌面或短时 VFX。

### Asset Gate

- 每个角色需要源文件、Web 可用导出、头像、正面/侧面/3/4 图。
- 桌面视角和移动端头像必须分别检查。
- 角色材质应接近手绘油画/蛋彩动物角色，不像 placeholder、几何体拼装、糖水萌宠或塑料玩具。
- 公开试玩前每个角色必须有 portrait、mobile-avatar、table-scale 和 detail QA，证明动物特征、表情、道具和服装层不是简单 primitive。
- 未经授权不得使用可识别真人肖像作为模型目标；当前方向也不再以真人复刻作为角色目标。
